If we were "live" I'd give you a moment to read the accompanying slide, and think about it. I'd like to emphasize that WHIRL focuses on answering queries that combine information from several Web sites. One problem that often surfaces in doing this is that different sites may have different names for the same thing. WHIRL stands alone (so far) in addressing this problem, which I believe to be very common.

The links in the accompanying slide provide a concrete example of the problem. Here are two information sources from the Web, each of which could easily modeled with a database. The Superkid site contains a single large table, spread out over several pages. (You can step through the table using the [A-Z] links at the top of each page). This table is pretty complete, but one thing is missing: the table names the publisher of each game, but doesn't provide a link to the publisher's home page. The Yahoo! pages (1, 2) list a number of game publishers, together with their home pages, and it's very natural to think about joining this information with the data from the Superkid site.

The problem with doing this "join" is that there are no good keys to use for the join. The only identifer for a company is its name, and the names vary quite a bit from one site to the next---and even sometimes within a site. As one example, please look at the different variants of "Microsoft" in these two sources.
