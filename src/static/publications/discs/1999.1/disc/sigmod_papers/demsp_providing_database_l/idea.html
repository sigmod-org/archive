The Main Ideas in WHIRL

  • Model the information sources as relations but don't clean up the keys.
    • Relation publisher(name,href)
    • Relation superkid(game,pub,category,priceinfo)
  • Use "similarity joins" to query the data; an answer is the K tuples that best satisfy the WHERE clause.

    •  
    FROM  publisher as p
    superkid as s
    WHERE  s.pub=p.name
    SELECT  s.game,s.pub, 
    p.name,p.href
    FROM  publisher as p,
    superkid as s
    WHERE  similar(s.pub,p.name)
    SELECT  s.game,s.pub, 
    p.name,p.href
  • Similarity is computed with cosine distance (widely used in information retrieval.) This works well in controlled experiments, and leads to an efficient query-processing algorithm.

    •  
  • Current implementation is memory-based and handles unions of select-project-join queries.
