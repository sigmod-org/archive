Step by Step

Step 1: The query

The user asks an OQL-like query. OQL stands for Object Query Language, like because the user expresses himself with his vocabulary and with the shortcuts corresponding to his understanding (or his laziness).
The query is sent to the Dispatcher.

Step 2: Query processing

The query is parsed and (1) relevant constants are extracted and (2) the target structure inferred from the query.

Step 3: IR query

Relevant constants (such as a topic "Web", a country "USA", etc.) are extracted from the user's query and used as parameters for a IR query sent to a search-engine.

Step 4: Target Structure

It consists of the structure explicitly expressed by the user in his query. All classes and attributes are extracted from the query and completed.

Step 5: View definition

When it is the first query, the the view definition consists in using the target structure as schema for the cache. In case of a refinement, the view definition consists of creation of new classes or specialization of already existing ones in order to extend the current schema to the target structure.

Step 6: Extraction

To populate the cache, retrieved documents (Calls for papers) are processed and expected data (such as "dates", "conferences names", "topic", etc.) is extracted.

Step 7: Output

The OQL query is now asked against the resulting database and the output (maybe formatted) is returned to the user.
