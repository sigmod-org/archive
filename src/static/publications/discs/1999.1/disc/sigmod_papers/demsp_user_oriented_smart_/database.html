A structured cache

When browsing, Web documents that have been selected are stored in a cache. The usual cache does not provide the user with any other access to documents than display. AKIRA cache is twofold: a first layer consists of Web documents as they have been retrieved from the Web, (2) a second layer is an object oriented database whose schema may correspond to either explicit structure of documents or to their implicit structure. Objects of the structured cache point to fragments, which are pairs consisting of a file name (the name of the Web document in the unstructured layer of the cache) and a span (position of the extracted data in the source document).

Before asking the first query the whole cache is empty. (The unstructured cache is empty. The object oriented database has no predefined schema, and no data.) When the user asks the first query, a IR query is sent to the Web to retrieve documents. The target structure is inferred from the user's query and used as a schema for the database. Then retrieved documents are processed and the database is populated with extracted data. An instance of an object class corresponds to an instance of a concept, and to maybe several fragments of maybe several documents.

Fragments

Information extraction efficiency can be measured using the notions of recall and precision. Recall is a measure of the amount of relevant information extracted compared to all the relevant information that could have been extracted. Precision is a measure of how much of the extracted information is really relevant.

On one side, a user may expect the best recall and precision from extracting tools in a system. On the other side, since no one can expect 100% recall and 100% precision, the fragment representation in AKIRA provides the user with an direct access to the measure of quality of extraction.

Moreover, the fragment representation may be used for further optimization. When interested in extracting information about given particular instances of concepts (such as SIGMOD for concept Conference), why processing the whole underlying understructured cache? Only files that mention the given instances should be processed. Each instance of a concept is associated to the list of its fragments. It then easy to only process files whose name appear in the first component of these fragments. The second component (span) of fragments, may also be used by extractors which are based on a notion of locality. In this latter case, why should an extractor process the whole file when it is only necessary to process a zone around a given string of characters, and when this particular string is directly accessible in the document with the span? The use of fragments may improve the extraction capabilities of the system and thus optimize evaluation of queries.
